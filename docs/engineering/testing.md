# Testing Scope

The contract that says, for each surface in the repo, what discipline applies and what is explicitly out of scope. Without this table, slices either over-test trivial glue or under-test load-bearing logic. With it, the answer is one row away.

A package under `internal/` or `pkg/` MUST appear in this table. The check is enforced by [`scripts/check-testing-doc.sh`](../../scripts/check-testing-doc.sh) (wired into `make check`). When a new package lands, the row lands in the same commit.

## Discipline glossary

- **TDD strict.** Failing test before implementation, every behavior. Red, green, refactor applies in full. Skeleton commits (empty `package x` files) are exempt until the first behavior lands.
- **TDD strict + race.** As above, and the package's test target runs with `-race`. Concurrency is load-bearing.
- **Fixture-backed.** Tests assert against captured fixtures rather than computed outputs. Used when the surface is shape-of-output (logs, JSON envelopes) and changes should be reviewed-as-fixtures.
- **Scenario-driven.** Tests model operator scenarios end-to-end (start daemon, send query, assert response). Slower than units; fewer in number; each one names a user-visible behavior.
- **E2E only.** No in-process tests; only subprocess or rig-level. Used where the boundary IS the contract.
- **Visual + a11y.** Snapshot + axe-core checks on the React surface. Owned by the dashboard slice.

## When the discipline doesn't fit

If a new surface doesn't match any row above, **add the row in the same commit that introduces the surface**. The discipline column is the contract; if the contract is wrong, fix it explicitly rather than silently widening an existing row's scope.
