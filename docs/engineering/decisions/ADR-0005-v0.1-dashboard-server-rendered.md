# ADR-0005 — v0.1 dashboard is server-rendered

**Date (UTC):** 2026-05-27
**Status:** Accepted
**Supersedes:** ADR-0001 §D10 (narrows scope: D10's React+Vite+Tailwind+shadcn stack applies once the dashboard surface requires interactivity beyond a refresh; v0.1 ships server-rendered)

## Context

ADR-0001 §D2 commits to "decoys + blocklists + CLI + read-only web dashboard" as the MVP+ v0.1 surface and §D10 names the web stack as "React + Vite + Tailwind + shadcn." The backend (`internal/web` Store + `/healthz` handler) shipped in earlier slices; the frontend never did. v0.2 (slow-path foundation) was completed over that gap.

For the v0.1 surface — a read-only operator dashboard with a single screen (recent decisions + uptime) consumed on the LAN — a full JS toolchain (pnpm + Vite + React + shadcn + the supply chain ADR-0002 §5 governs) is disproportionate. The same operator value (a browser-loadable read-only page) is deliverable with the Go stdlib `html/template` package, an embedded template file, and inline CSS using DESIGN.md tokens. Zero Node, zero build step.

## Decision

For the v0.1 dashboard surface, render server-side from `internal/web` using Go `html/template` and `embed`. Inline `<style>` block keyed off DESIGN.md tokens. Polling refresh via `<meta http-equiv="refresh">`. No JS toolchain in `web/` at launch.

D10's React + Vite + Tailwind + shadcn stack remains the project's web stack of record. This ADR scopes D10 to "applies once the dashboard requires interactivity beyond a refresh" — filters, drill-down, live SSE / WebSocket transport, the operator-action surfaces that arrive with v0.3+.

## Consequences

- The launch dashboard ships in a single Go slice (no `package.json`, no `pnpm install`, no postinstall surface). Lowers the v0.1 attack surface and makes the launch installable on minimal hardware (Raspberry Pi 5) without a JS runtime.
- The eventual React port is a port, not a rewrite — the data contract (`internal/web.Store.SnapshotAll`) is already shaped for a list view.
- DESIGN.md tokens live in two places at launch: the YAML at the top of `DESIGN.md` and the inlined CSS variables in `internal/web/templates/index.html`. The React port collapses this. Until then, the two copies are kept in sync by hand; drift is caught at code-review time.

## Revisit conditions

- The dashboard needs interactivity (filters, drilldown, manual override actions) — at that point, port to the D10 stack as a real sub-project.
- A second `internal/web` page lands that would duplicate the inline-CSS approach to the point that a stylesheet is warranted.
- An operator reports the meta-refresh is a problem in their workflow (e.g., interrupts text selection during incident triage).
